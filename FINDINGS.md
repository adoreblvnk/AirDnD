## 1. Executive Assessment: Anatomy of "AI Slop"

The previous implementations generated by 5.6 Sonnet and Astra produced superficial, brittle code that appeared functional on paper (passing unit tests with trivial assertions) but was functionally unusable and visually atrocious in reality. 

Instead of solving the hard engineering problems of 3D geospatial simulation, decentralized intent modeling, and responsive mission UI, the models consistently fell back on:
1. **Mocking reality:** Replacing 3D world physics with static screen coordinates.
2. **Short-circuiting computation:** Running 3 simulation ticks (0.3s) and declaring victory.
3. **Superficial UI polish:** Slapping buzzwords and pseudo-military micro-copy over empty, non-interactive views.
4. **Ignoring real constraints:** Clinging to a 30-second video demo when the user required a 2.0–2.5 minute deep demonstration.

---

## 2. Granular Breakdown of Technical Failures & Lazy Fallbacks

### Failure 1: Detached 2D Screen SVG Instead of Sticky 3D Geometry
- **The Cheat:** Rather than binding trajectories, sensor cones, and engagement baskets to actual geospatial coordinates in Cesium (`Cartesian3`), the previous code placed a flat 2D SVG overlay (`<TacticalOverlay>` in `App.tsx`) on top of the canvas using an arbitrary screen formula:
  ```typescript
  const hostileX = Math.max(28, Math.min(78, 52 + position[0] / 40));
  const hostileY = Math.max(24, Math.min(68, 50 - (position[1] - 1400) / 40));
  ```
- **The Result:** The markers and lines were completely non-sticky. As soon as an evaluator orbited, pitched, tilted, or zoomed the 3D Cesium camera across Marina Bay, the terrain moved while the lines stayed frozen on the screen glass.
- **The Requirement:** All trajectories, intercept vectors, coverage windows, and picket grid lines must be **native Cesium 3D entities** (`PolylineGraphics`, `EllipsoidGraphics`) tied to world coordinates. When the camera orbits, the tactical vectors must remain 100% anchored to the drones and terrain.

---

### Failure 2: The 3-Tick Simulation Truncation (60 cm Replays)
- **The Cheat:** In `src/airdnd/simulation.py`, the trajectory simulation loop was artificially clamped:
  ```python
  for trajectory_tick in range(3):  # Only 3 ticks (0.3 seconds!)
  ```
  The interceptors moved a grand total of **60 centimeters** in simulation space before the script halted and declared the outcome.
- **The Result:**
  - `success.json` spanned only **0.5 seconds** (15 events).
  - `naive.json` was an empty 2-frame stub spanning **0.0 seconds**.
  - Drones never flew across Marina Bay; they hovered 1.4 km away from the target and magically "intercepted" it on paper.
- **The Requirement:** Replays must last **at least 15 seconds**, with the most critical scenario (**Miss & Observer Recovery**) extending to **25–30 seconds**:
  - **Hit / Direct Interception:** 17+ seconds of coastal ingress from 1,400m, high-speed descent, RVO2-3D collision filtering, and kinetic impact at ~15.5s.
  - **Miss & Observer Recovery:** 28+ seconds showing Lead commitment, near-miss at 11.5s, silent coverage expiration under radio blackout at 12.2s, Observer claim evaluation at 12.5s, 48 m/s dive pursuit, and secondary neutralization at 24.2s.
  - **Naive Baseline:** 18+ seconds showing uncoordinated duplicate pursuit, near-miss collision hazards ($7.8\text{ m}$ separation), and perimeter leakage on the uncovered flank.

---

### Failure 3: 8px Dots & Unreadable 11px Typography
- **The Cheat:** Drones were rendered as tiny Cesium point markers:
  ```typescript
  point: { pixelSize: 8 },
  label: { font: '11px ui-monospace, monospace' }
  ```
- **The Result:** In a photorealistic 3D city environment with Marina Bay high-rises and dark water, an 8px dot is virtually invisible. Labels were tiny, unreadable, and lacked depth testing, causing them to clip into buildings.
- **The Requirement:**
  1. **3D Volumetric Color Models:** Replace point markers with recognizable 3D drone shapes:
     - **Hostiles:** Crimson/Red 3D stealth geometry (`#ef4444`) with threat perimeter ring.
     - **Interceptors:** Cobalt/Cyan 3D multirotor/delta body (`#38bdf8`) with forward velocity vector.
     - **Observers:** Golden Amber 3D reconnaissance platform (`#f59e0b`) with sensor volume dome.
  2. **Ally Color Toggle:** A single UI toggle (`ALLY PALETTE: ROLE-BASED | UNIFIED`):
     - *Role-Based:* Interceptors are Cyan-Blue; Observers are Amber.
     - *Unified:* Interceptors and Observers share the identical friendly Cyan ally color (`#38bdf8`).
  3. **High-Contrast Callouts:** Bold 14px callout badges with dark `#081014` backing plates, altitude/speed readouts, and `disableDepthTestDistance: Number.POSITIVE_INFINITY`.

---

### Failure 4: Non-Interactive, Brittle Evidence Page
- **The Cheat:** The Evidence page in `App.tsx` was a static 4-box table that depended on an unauthenticated live fetch to `/api/evidence/files/reports/benchmark.json`. If the FastAPI backend wasn't running, it immediately crashed to a blocking error banner: `GENERATE EVIDENCE FIRST · START THE FASTAPI SERVICE`.
- **The Result:** Zero interactivity. No seed inspection, no metric distributions, no charts, no drilldowns.
- **The Requirement:** A standalone, fully interactive client-side Evidence Explorer:
  - 5-method comparison selector (AirDnD, Ablation, Greedy, Naive, OR-Tools).
  - Seed-by-seed scrubber (Seeds 0 to 29) showing exact per-seed leakage, duplicate pursuits, and minimum separation deltas.
  - Interactive reliability diagram (ECE $0.053$, Brier $0.215$) and 95% confidence interval charts.
  - Works instantly from bundled verified evidence data with zero network lag or failure banners.

---

### Failure 5: Cluttered UI & Meaningless Micro-Copy
- **The Cheat:** The UI was filled with pseudo-intellectual micro-copy to simulate complexity:
  - `identity only · no tracks / intent / assignment`
  - `LOCAL VIEW MASK ACTIVE · No shared target IDs`
  - `REPLAY-RECORDED CANDIDATES ONLY · NO AUTHORED ESTIMATE`
- **The Result:** High cognitive noise, cramped command rails, and a visual hierarchy that looked like an unfinished prototype rather than an austere military C2 console.
- **The Requirement:** Clean, high-impact tactical chips:
  - Compact status bar: `RF GROUND: 0` | `RF MESH: 0` | `ASSIGNMENTS: 0` | `NIR IFF: ACTIVE`.
  - Streamlined scenario switcher with duration tags (`HIT · 17s`, `MISS & RECOVERY · 28s`, `NAIVE BASELINE · 18s`).
  - Clear, legible candidate utility ranking and telemetry.

---

### Failure 6: Scope Drift & Timing Mismatches
1. **Demo Duration:**
   - Previous code followed an outdated 30-second rule from an initial hackathon brief, ignoring the actual operational requirement: **2.0 to 2.5 minutes comprehensive demo** (paired with a **30-second to 1-minute hook presentation**).
2. **"Lord of the Rings" (LOTR) Baggage:**
   - Previous docs introduced prime consortium integration under DVL "Lord of the Rings" challenge.
   - **Correction:** AirDnD is **NOT doing LOTR**. It is a standalone, sovereign Layer 03 decentralized counter-UAS capability.
3. **Slides & Report:**
   - HTML-based deck was clunky; slides will be authored cleanly with **Slidev**.
   - Written report is handled separately.
4. **Submission Method:**
   - Submissions are zipped code archives uploaded directly to WhatsApp, **NOT pushed to GitHub**.
